## Architecture

Personal portfolio, live-demo led on an editorial static shell. Next.js 14.2 App Router, TypeScript, Tailwind 3.4, React 18. **Direction C — hard monochrome brutalism**: true-black ground, white ink, two grey steps, hairline rules, no accent hue. The black↔white row inversion carries all emphasis (there is no colored accent; the earlier teal and the proposed `#4B2BFF` blue were both dropped — pure monochrome is locked). The `<html>` element no longer carries a `dark` class; it carries the three font CSS-variable classes and `body` is `bg-bg text-fg`.

**Content is code, and it is the only source of truth.** All displayed content (owner, case studies, experience, skills) lives in `lib/data.ts` as typed exports — no CMS, database, or fetch. Every content shape (`CaseStudy`, `Experience`, `SkillGroup`, etc.) is typed at the top of that file. Facts come from the user's resume only; no invented projects, metrics, or dates. `decisions: []` means "not yet gathered," never faked.

**Server-first.** Everything renders as React Server Components by default, so all content is in the server HTML (readable JS-off, crawlable). There is no `ssr: false` on content and no boot animation in front of the LCP element.

**Page composition.** `app/page.tsx` (server) renders `<Cursor />` and `<GridLines />` first (both decorative, behind everything), then a `<div className="relative z-10">` wrapper holding `Navbar` → `Marquee` → `<main>` (`Hero` LCP-safe H1 → `Stats` → `Work` → `ProjectIndex` → `Experience` → `Skills` → `Reach` → `Testimonials` → `Contact`) → `Footer`. The wrapper sits above `GridLines` (z-10 over z-0). A decorative `<GrainOverlay />` (fixed film-grain SVG noise, `z-[60]`, `pointer-events-none`, `mix-blend-soft-light`) is mounted globally in `app/layout.tsx`. No `next/dynamic` on content. Sections live in `components/sections/*.tsx`, server components except where a client island is required.

**Client islands (only these).** `Navbar` (mobile menu toggle), `Contact` (form posting to `/api/contact`, with a visible `mailto:` fallback that works JS-off), and `Cursor` (decorative, pointer-fine only). Case-study interactive artifacts are lazy, facade-gated client islands (see below).

**Case-study pages.** `app/projects/[slug]/page.tsx` is statically generated from the `caseStudies` array in `lib/data.ts` (`generateStaticParams` + `generateMetadata` both read it). Each page renders: header (category/status/problem/live+repo links), meta grid, stack chips, an architecture diagram, `chose/rejected/why` decision cards (rendered only if `decisions.length > 0`), and the interactive artifact. Adding a case study to the array creates its page automatically.

**Case-study artifact system** (`components/casestudy/`). The interactive proof degrades to static with JS off:
- `Architecture.tsx` — registry mapping a `architecture.component` string to a diagram; falls back to the caption in a dashed box.
- `PipelineDiagram.tsx` — server-rendered labeled-stage flow (down-arrows on mobile, right-arrows at `lg`), optional feedback-loop caption.
- `ArtifactFrame.tsx` — the facade. Renders the static fallback (its children) until "Run interactive demo" is clicked, then lazy-loads the live widget via `next/dynamic({ ssr: false })`. Keeps the widget out of first-load JS.
- `CodeCanvasWidget.tsx` — the live, dependency-free interactive island (draw boxes → generate React + Tailwind).
- `CodeCanvasStatic.tsx` — the server-rendered static preview used as the JS-off fallback (no poster PNG needed).

**Contact form.** `app/api/contact/route.ts` validates fields, then sends via Resend (`RESEND_API_KEY`). With no key set it logs the submission and returns success (the visible `mailto:` link is the user fallback, so nothing is lost). `CONTACT_FROM` overrides the sender; defaults to Resend's shared onboarding sender until a domain is verified. Delivers to `owner.email`.

**SEO / metadata.** `app/layout.tsx` sets `metadataBase`, title template, OG/Twitter, and injects `Person` JSON-LD; case-study pages inject `CreativeWork` JSON-LD. `app/sitemap.ts` and `app/robots.ts` are generated (robots disallows `/styleguide`). Favicon is `app/icon.svg` (monogram, no binary). **OG images are generated, not static**: `app/opengraph-image.tsx` (home) + `app/projects/[slug]/opengraph-image.tsx` render a brutalist mono card via `next/og` from `lib/ogTemplate.tsx` (default satori font — the local woff2 can't feed satori); `twitter-image.tsx` files re-export them. They are `export const dynamic = "force-dynamic"` (on-demand) because `@vercel/og`'s wasm/font loader throws on the local Windows project path (it contains a space, `Portfolio website`); on Vercel's Linux runtime they generate fine at request time. The old static `/og.png` metadata references were removed. **Vercel Analytics** (`@vercel/analytics/react` `<Analytics/>`) is mounted in the layout.

## Styling

Design tokens live in `tailwind.config.ts`, not scattered in components — see that file's header comment. **Monochrome only, no accent hue.** **ONE sanctioned colour exception (user override, 2026-08-19): project client-country flags** — small colored inline SVGs in `components/graphics/Flag.tsx` (Pakistan, Ghana), shown in Work rows + case-study headers next to the category/status. Deliberate colour, do NOT strip them as a mono violation. Not emoji (Windows has no flag glyphs); real SVGs. This is the only place hue is allowed; everything else stays pure mono. Colors: `bg #000000`, `fg #FFFFFF`, `mut #8A8A8A` (secondary text, ~6.1:1 AA on black), `faint #6A6A6A` (~3.9:1 — large decorative numerals only, clears the 3:1 large-text floor; informational small text uses `mut`, never `faint`), `card #0A0A0A` (near-black hover wash), `line`/`line2` (hairline rules at 16%/30% white). Corners are sharp: `borderRadius` defaults to `0` (only `full` kept for the rare pill). Also defined: a tight-leading/negative-tracking type scale, `letterSpacing.tightest`, motion timing/duration tokens, and keyframes `marquee` / `char-in` (hero mask reveal) / `reveal-up`.

Two display registers on purpose so the type is not one flat note: **Unbounded** caps for the shout (hero PRODUCTION/SOFTWARE, section numerals 01–05) vs **General Sans** mixed-case at display scale for titles and body. **JetBrains Mono** for labels only. Unbounded + JetBrains Mono are wired via `next/font/google` (`--font-unbounded` / `--font-jetbrains`). **General Sans is NO LONGER next/font** — it is self-hosted via a manual `@font-face` in `app/globals.css` on a stable `/public/fonts/*.woff2` path (weights 400/500/600, `display:swap`), tailwind `font-sans` points at the `"General Sans"` family directly, and `app/layout.tsx` `<head>` preloads the Regular + Medium weights. Reason: next/font would not emit a font `<link rel=preload>` in this setup (fonts consumed only through Tailwind CSS vars, so Next can't see them as "used"), and the hero pitch `<p>` is the LCP element — the un-preloaded font-swap was the LCP render-delay. Self-hosting lets it be explicitly preloaded. (Inter is gone.)

The hero H1 is the LCP element and paints immediately (no JS gate). Its caps use a pure-CSS staggered mask reveal (`.rmask` overflow-hidden box + inner span sliding up, per-word inline `animationDelay`), static under reduced-motion. Caps size is `clamp(2.5rem,10.6vw,9rem)`, tuned so the final glyph loses at most ~40% to edge-bleed and never a whole letter across 1280/1440/1920. `Work` is not a card grid: full-bleed hairline rows, row 0 the taller spotlight, title side alternating left/right (`i%2`), each row inverting black↔white on hover.

Global CSS (`:focus-visible` white ring, `::selection` white-on-black, `.rmask`, `.cursor-dot`, `.js-reveal [data-reveal]` scroll-reveal, `.hero-extrude` 3D word, reduced-motion guard that also kills the cursor + smooth-scroll, coarse-pointer cursor hide, scrollbar) is in `app/globals.css`.
